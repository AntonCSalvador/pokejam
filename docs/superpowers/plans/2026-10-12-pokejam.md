# PokéJam Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a complete browser basketball match with two Pokémon per team, private online rooms for up to four humans, AI replacements, and signature moves.

**Architecture:** One Node process serves static files and authoritative matches over WebSocket. Browser clients use native Canvas, shared movement rules for local prediction, and server snapshots for ball, score, and opponents. State stays in memory; no framework, database, or general game engine.

**Tech Stack:** JavaScript ES modules, Canvas 2D, native browser WebSocket/Web Audio, Node built-ins, `ws`, and `node:test`. Local runtime inspected: Node 24.14.0 and npm 11.9.0. Select and lock a compatible `ws` version during execution; no package installation during planning.

**Spec:** [Approved first-playable design](../specs/2026-10-12-pokejam-design.md). Read both documents before executing.

## Global Constraints

- "Desktop browsers and keyboard controls for the first version."
- "A three-minute match, followed by first-basket-wins overtime if tied."
- "Private rooms without accounts, matchmaking, spectators, or chat."
- "Chicago and Miami occupy fixed opposite sides in the first version; each roster member appears once."
- "Start with a 60 Hz simulation and 20 Hz snapshots."
- "Release movement when input goes stale for 250 ms."
- "Reserve the disconnected human's control assignment for 60 seconds while AI plays."
- "Empty rooms expire after two minutes."
- "For the first single-process build, cap active rooms at 16 and return a readable busy message at capacity."
- "Render at a fixed low internal resolution, initially 640 × 360, with nearest-neighbor scaling and letterboxing."
- "Real internet verification uses separate computers on separate networks. Until run, internet play remains unverified even if localhost passes."
- Keep the game in this separate repository; do not change the adjacent REA checkout.
- Every task inherits the spec's scoring, animation, ownership, accessibility, and failure requirements. No hidden reduction to local-only or placeholder-only completion.

## Review Focus

1. A quick press and release arriving together must trigger exactly one action, even if a snapshot is skipped. Exercise input edges and acknowledged input in Tasks 2, 4, and 6.
2. A duplicated tab or reconnecting old socket must never leave two concurrent controllers or take an unrelated Pokémon. Exercise token replacement and control generations in Task 4.
3. A shot released on the last tick must resolve once before a winner or overtime is chosen; an opponent must still be able to block it. Exercise Task 2's buzzer cases.
4. A browser losing focus while moving, turboing, or charging must not leave held controls active. Exercise Task 5's focus check and Task 4's stale-input check.
5. A partially missing sprite sheet must leave the match usable while making incomplete art visible; loading failures cannot become silent completion. Exercise Task 1's manifest check and Task 5's fallback check.

| `docs/verification/first-playable.md` | Observed acceptance results, environment, remaining limits |

Keep rules independent of sockets and DOM. Use plain objects and named functions, not service interfaces or factories for hypothetical implementations.

**Simulation schema:** `Match` contains `tick`, `seed`, `phase` (`countdown`, `live`, `deadball`, `buzzer`, `finished`), `overtime`, `remainingMs`, `shotClockMs`, `score: [number, number]`, `players`, `ball`, and `events`. Player IDs are stable integers 0–3: Tauros/Machamp on team 0 and Heatmor/Charizard on team 1. Each player carries position, velocity, jump height, facing, turbo, meter, action timing, and pending signature state. Human ownership belongs to rooms, not the physics object. Ball mode is `held`, `flight`, or `loose`; flight records pass/shot/dunk kind, release position, originating player/team, and one resolution ID. Keep event IDs increasing across a match so clients cannot replay score sounds on repeated snapshots.

**Input schema:** `Input = { seq, controlEpoch, x, y, held, pressed, released }`, with finite axes in [-1, 1] and bitfields for turbo, pass/steal, shoot/block, signature, and switch. `pressed`/`released` preserve short taps; a held button alone cannot retrigger an edge action. Normalize diagonal movement. One packet represents one 1/60-second control sample. Never accept a client-provided delta time, player ID, position, or score. Control epoch increments when an assignment changes or reconnect replaces a socket, invalidating queued input for the old assignment.

## Task 4: Serve authoritative rooms and resilient online sessions

**Files:** Create `server/rooms.js`, `server/index.js`, `test/rooms.test.js`, `test/server.test.js`; update package/lock.

**Interfaces:** `createRooms({ now = Date.now }) -> manager` returns `connect(send) -> connectionId`, `receive(connectionId, message) -> void`, `disconnect(connectionId) -> void`, and `tick() -> void`. `tick` advances each active match by `DT`, applies ownership changes, runs bots, and emits personalized snapshots every third tick. `send(message)` receives plain objects. Inject `now` for reservation/expiry tests; simulation time remains fixed-step.

Export `startServer({ port=0, host='127.0.0.1', now=Date.now }) -> Promise<{ url, close }>` from `server/index.js`; only the CLI entry starts a listening server automatically. `close() -> Promise<void>` stops sockets, timers, and HTTP. CLI accepts `PORT` and `HOST`, and can bind `0.0.0.0` for deployment.

**Protocol:** Every message has a `type` discriminant. Client types are `create`, `inspect { roomId }`, `join { roomId, slot }`, `claim { slot }`, `start`, `input { ...Input }`, `reconnect { roomId, token }`, and `rematch`. Server types are `welcome { roomId, token, slot, controlEpoch }`, `lobby { roomId, host, slots }`, `snapshot { match, slot, controlEpoch, ackSeq }`, and `error { code, message }`. Room creation assigns slot 0; `inspect` returns public lobby availability before a visitor picks a slot and does not subscribe them to match snapshots. Joining requires a specific free slot. Public lobby data never contains reconnect tokens. `claim` changes slots only in lobby; late joining uses `join` and reserves the slot until a dead ball.

- [ ] Install and pin `ws` as the only production dependency; keep the generated lockfile. Run one import check so subsequent failing tests expose absent behavior rather than a missing dependency.
- [ ] Add deterministic room tests using an injected clock and array collectors for outgoing messages. Assert four unique assignments, atomic slot races, one-human switching, two-human refusal, late-join reservation, host transfer, 16-room cap, 250 ms stale inputs, 60-second reservation expiry, and 120-second empty-room cleanup. Pin the token race:

  ```js
  assert.equal(newestSnapshot.players.length, 4);
  assert.equal(newWelcome.slot, oldWelcome.slot);
  assert.ok(newWelcome.controlEpoch > oldWelcome.controlEpoch);
  assert.equal(oldSocketCommandResult.code, 'SESSION_REPLACED');
  assert.equal(fifthJoinResult.code, 'ROOM_FULL');
  ```

  In these fixtures, `newestSnapshot` is the `match` field of an emitted snapshot; messages are captured by the test's `send` callback. After an old-socket input, tick once and assert the reclaimed character remains at its pre-input position.
- [ ] Add real HTTP/WebSocket integration tests using `startServer` on an ephemeral port and four `ws` clients. Check static responses, a complete match snapshot exchange, full room, bad room ID, malformed JSON, non-finite/out-of-range axes, unknown fields, oversized input, excess input, bad Origin, and encoded traversal requests. Assert invalid traffic cannot alter score or another slot and cannot crash the server. Cleanup in test hooks closes every resource.
- [ ] Run `node --test test/rooms.test.js test/server.test.js`; expect absent implementation or behavioral failures until implemented.
- [ ] Implement rooms and validated protocol. Generate room IDs and separate 32-byte tokens with Node crypto. Limit accepted packets to 4 KiB and 120 per second per socket, with a per-controller input queue capped at 15 frames; consume at most one movement frame per simulation tick. Acknowledge only consumed inputs, discard stale epochs, and preserve action edges. Handle excess queued traffic without letting client packet volume accelerate simulation.
- [ ] Implement monotonic fixed-step scheduling with bounded catch-up after stalls; session deadlines use injected wall time. Ping at one-second intervals and drop silent sockets by five seconds. An explicit disconnect immediately installs AI. Reconnect atomically replaces the prior socket, rotates its token, increments the control epoch, clears stale queued inputs, and preserves its Pokémon. Reserved and pending slots are excluded from Space switching.
- [ ] Serve only allowlisted content types from the resolved `public/` root. Decode/check paths before reading; reject traversal and outside-root symlinks. Same-origin browser sockets only; local test clients supply a matching Origin. Do not log session tokens. Bound pre-join connections and close idle unaffiliated sockets after 10 seconds. Use one process with in-memory rooms.

## Task 6: Smooth movement and reconnect without corrupting outcomes
